# KawazuNext 図面スキャン

試験公開：https://y-kawazu.github.io/drawing-scan/

ソース：https://github.com/y-kawazu/drawing-scan

2026-11-01：GitHub Pages（main / root、HTTPS）で試験公開。公開URLでサンプルの補正・JPG生成準備・オフライン用キャッシュ完了を確認済みです。iPhone・Androidの実機撮影、インストール、メール添付は未検証です。

サーバープログラム不要の日本語PWA。撮影画像の画素をOpenCV.jsとCanvasで補正します。画像生成AI、OCR、外部処理API、SMTPは使用しません。

## 起動

Windows PowerShellでこのフォルダーに移動し、Node.jsを使用します。

```powershell
cd D:\GoogleDrive\Application\drawing-scan
node server.cjs
```

ブラウザーで http://localhost:4176 を開きます。停止はCtrl+C。ビルド・npm installは不要です。file://で直接開く方法はWorkerとPWAが動かないため使用しません。スマートフォンからPCのlocalhostにはアクセスできません。スマートフォンはHTTPS公開後に確認してください。

## 操作

1. カメラ・写真・ファイルから1枚取り込む。PCはドラッグ＆ドロップ対応。「サンプルで試す」で動作確認できます。
2. 「自動補正する」を押す。「標準」は明るさ40・コントラスト20・背景白色化160・シャープネス100・ノイズ軽減100・赤色保護200です。すべてのスライダーはこの標準値で中央になります。写真の取り込み成功時は毎回「標準」に戻ります。赤色保護の100超は淡い赤にも保護を強め、画素の合成率は100%以内に制限します。「すべての補正をリセット」でもこの値に戻ります。弱・標準・強のプリセットと6種類のスライダーでも調整できます。
3. 原本・補正後・左右比較を切り替え、拡大して25/27、品番、赤線、薄い鉛筆線を確認します。ピンチ・ドラッグ・マウスホイール対応。
4. 必要なら90度回転、±15度の手動傾き調整、四隅の台形補正を使用します。四隅は左上→右上→右下→左下。台形補正は選択外を切り取るので図面全体を囲んでください。自動の角度推定は未実装です。
5. 「JPG保存」または「共有・メール送信」。ファイル名は `元ファイル名_補正.jpg`、初期品質95%。共有先メールアプリで連絡先から宛先を選びます。

共有用Fileは補正完了後に事前生成し、タップのハンドラー内で直接 `navigator.canShare({files})` と `navigator.share({files,title,text})` を実行します。HTTPSが必要です。共有の件名・本文はアプリ次第で無視されます。キャンセルは正常扱い。未対応時はJPGを保存して手動添付してください。mailtoによる添付代替は行いません。OSの保存完了・メール送信完了はWebアプリから検知できないため、「保存完了」と断定しません。iPhoneでダウンロードできないときは共有から「ファイルに保存」を使用してください。送信先やメール添付は実機のOS・メールアプリに依存します。

## 正確性と画像処理

- 原本Fileと未補正Canvasをメモリに保持し、書き換えません。ページを閉じると画像は消えます。元のファイルは削除しません。
- OpenCVの縮小画像上でクロージング・GaussianBlurを使ってRGB別の背景照明場を推定。推定した紙の背景を先に白へ近づけ、そこから元の線との濃度差を差し引くことで黄ばみ・影・照明むらを軽減します。明るさによる紙の白飛びと細線の白飛びを分離します。さらに連続的な濃度カーブで既存の文字・線を濃くし、小さな紙の濃度むらを抑えます。「白黒＋赤字」では赤以外を白黒に近づけてカメラの色ノイズを抑えます。二値化や線の再描画は行いません。強い二値化はしません。
- 512×384画素＋境界余白のタイルでGaussianBlur、エッジを保護するバイラテラルノイズ軽減と、微細な揺らぎを増幅しない強度制限付きシャープ処理を行います。暗い影や強い色かぶりの完全除去は保証しません。
- 黄ばみのR>G>Bの色かぶりを除外して赤の優勢画素を検出し元の色を優先。OCRや文字認識による数字・文字の置換は一切ありません。赤色検出にも限界があります。
- シャープネス・コントラスト・JPEG圧縮・幾何変換・縮小により線や文字が劣化する可能性があります。補正後は必ず比較確認してください。寸法の正しさは利用者が原本と照合します。
- 回転は画像全体を収める白いキャンバスに等倍描画します。斜め回転では余白によりキャンバス寸法が増えますが、画素を引き伸ばしません。台形補正はOpenCV warpPerspectiveで手動指定範囲を変換し、出力辺・面積を入力以内に制限します。
- 幾何変換後は位置を揃えた未色補正画像と比較します。完全な原本表示に戻す場合は「回転・台形補正を原本に戻す」または「すべての補正をリセット」を押してください。
- 通常は読み込み解像度を維持。60MB超は拒否。モバイル12百万画素、PC20百万画素、長辺8,192pxを超える画像は縮小の同意を求めます。無断では縮小しません。ブラウザーのデコード段階で巨大画像が拒否される場合はJPG化・縮小して再試行してください。HEICはOS・ブラウザーがデコードできる場合のみ対応し、独自変換はしません。
- EXIF回転は `createImageBitmap(...,{imageOrientation:'from-image'})`、未対応時はブラウザーのImageデコードを使用。CanvasでEXIFや位置情報は出力に引き継ぎません。sRGBキャンバスからJPEGを書き出し、ICCプロファイル埋め込みまでは保証しません。
- Worker内で処理しUIを分離。OpenCVのMatはfinallyで解放。処理失敗・タイムアウトは日本語で案内します。ブラウザー強制終了まで完全には防げません。

## PWA・インストール

HTTPSで一度開き「オフライン準備完了」を待ちます。約10MBのOpenCV.jsもローカルにキャッシュします。キャッシュはブラウザーに削除されることがあるため、通信のある場所で起動確認してください。

- iPhone/iPad：Safari → 共有 → ホーム画面に追加 → 追加。
- Android：Chrome → メニュー → アプリをインストール／ホーム画面に追加。
- Windows Chrome/Edge：アドレスバーのインストールボタン。

manifestのstandaloneとアイコン・起動背景色を設定。iOSの起動表示はapple-touch-iconとOS標準の生成に依存し、端末別の静止スプラッシュ画像は同梱していません。縦横回転を制限しません。

更新時は `service-worker.js` のVERSIONと `app.js` のofflineStatus内キャッシュ名を同時に増やしてください。起動中の作業を保護するためskipWaitingはしません。更新通知後は保存して全タブ・ホーム画面アプリを閉じ、再起動します。SWが変わるのでHTML等のキャッシュもまとめて置き換わります。

## GitHub Pages試験公開・更新

公開するのはアプリの静的ソース・アイコン・OpenCV本体だけです。顧客図面はリポジトリに追加しないでください。

1. 専用GitHubリポジトリを作成。公開可否を確認してください（公開リポジトリではソースも閲覧できます）。
2. このフォルダーの `index.html`、`style.css`、`app.js`、`processor.js`、`manifest.webmanifest`、`service-worker.js`、`.nojekyll`、`icons/`、`assets/` をルートに配置してpush。
3. Settings → Pages → Deploy from a branch → main / root → Save。
4. デプロイ成功後 `https://ユーザー名.github.io/リポジトリ名/` を開く。全パスが相対指定なのでサブディレクトリにも設置できます。
5. 実機でインストール、オフライン起動、補正、保存、共有、メール添付・連絡先選択を確認してください。

既存サイトには同じ静的ファイルを `/drawing-scan/` にアップロードし `https://既存ドメイン/drawing-scan/` を開きます。PHP不要。既存のルートService Workerがある場合はキャッシュ・スコープ競合を確認してください。SWはこのサブディレクトリだけを管理します。ホスト側で外部解析タグを挿入しないでください。JS/CSS/manifestのMIMEとHTTPS、Worker・WASMがCSPでブロックされないことを確認します。推奨レスポンスヘッダー：X-Content-Type-Options: nosniff、Referrer-Policy: no-referrer。HTTPSはホスティング側で提供します。

## プライバシー・セキュリティ

「画像補正はお使いの端末内で行います。画像はKawazuNextのサーバーには送信されません。」

ネットワークは同一オリジンの静的ファイルとSW更新のみ。ユーザー画像へのfetch・XHR・解析・クラウド保存・永続化はありません。処理Workerへは端末内の転送だけです。ファイル名はtextContentで表示し、HTMLには挿入しません。SVG等の対象外形式は拒否。CSPで外部通信・外部スクリプト・object・formを制限。ユーザーが共有操作をした場合のみ選択したOSアプリへJPGを渡します。

## テスト

`node tests/processor.cjs` で同梱の本物のOpenCVと実際のprocessor.jsを使用して、原本の不変・1画素の薄線・赤色・台形変換を検証できます。PowerShellで `$env:STRESS='1'; node tests/processor.cjs` とすると4,000×3,000画素を処理します。ブラウザー操作の結果と実機未検証項目は `TEST-RESULTS.md` を参照してください。テスト画像はコードで作った架空図面であり、顧客図面ではありません。

## ファイル・依存

`index.html` / `style.css` / `app.js`：UI・読み込み・比較・JPEG・共有。`processor.js`：OpenCV Worker。`service-worker.js`：静的キャッシュ。`manifest.webmanifest` / `icons/`：PWA。`server.cjs`：ローカル起動専用。

OpenCV.js 4.10.0（@techstark/opencv-js 4.10.0-release.1配布）を `assets/opencv.js` に固定同梱、実行時CDN不要。OpenCVはApache-2.0、同梱ライセンス参照。生成AIや有料ライブラリは使いません。

技術資料：[OpenCV幾何変換](https://docs.opencv.org/4.10.0/dd/d52/tutorial_js_geometric_transformations.html)、[OpenCVフィルター](https://docs.opencv.org/4.10.0/dd/d6a/tutorial_js_filtering.html)、[Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)。

開いている画面に古いキャッシュが残る場合は、ローカルサーバー起動中に `http://localhost:4176/index.html?v=18` を開いてください。旧キャッシュを避けるためアプリとWorkerのURLに版番号を付けています。顧客画像は持ち越しません。フッターに「白紙スキャン補正 1.7」と表示される版が更新版です。

## スマートフォン画面（1.4）

冒頭の紹介文を削除し、①取り込み→②補正→③プレビューの順に配置。補正強度・スライダー・回転・保存設定・リセットは「補正の強さ・詳細設定」にまとめ、初期状態は閉じます。画像情報も折りたたみ、比較位置スライダーは左右比較時だけ表示します。プレビューは画像の縦横比に合わせて余白を減らします。全体表示では画像を中央に固定し、拡大時は画像の端まで移動できます。空白の外へ画像が消えるような移動は制限します。`node tests/viewport.cjs` で移動制限・表示順・初期折りたたみを確認できます。

## カラー補正（1.5）

初期状態と写真取り込み時は「カラー」。折りたたみの「補正の強さ・詳細設定」を開くと「カラー／白黒＋赤字」を選べます。切替時は原本から再補正し、JPGも選択した仕上がりになります。カラーでは紙の白色点と共通の明るさ補正で赤・青・緑・黄などの線や色塗りを残します。無彩色に近い背景は従来のノイズ抑制を使います。用紙の色とインク色が近い場合や、紙の白い領域が少ない写真では色の判別・再現に限界があり、撮影前の色を正確に復元する機能ではありません。原本比較で確認してください。`node tests/color.cjs` で広い色塗り・薄線・白紙化・色ノイズ・原本不変・白黒モードを確認できます。
